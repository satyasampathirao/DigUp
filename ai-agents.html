Why give your agent DigUp

An AI agent can read a page and write out a table itself. That is fine for a few rows. For real lists, DigUp does the collecting:

Connect MCP apps

About two minutes. You need DigUp 1.2 or later and Node.js 18 or later. Nothing else to install.

  1. Open DigUp's AI tools page

    Open DigUp's side panel, click the … menu and choose AI tools. If DigUp asks, press Allow DigUp on all sites: agents read pages without you clicking DigUp's icon each time.

  2. Turn on "Connect AI tools on this computer"

    The page shows your pairing code and the port (47615 unless you change it).

  3. Download the DigUp MCP server

    Press Download digup-mcp.mjs. It is one small file that talks only to DigUp, on 127.0.0.1 (your own computer).

  4. Add it to your app

    The AI tools page shows both of these with your own code and path filled in, ready to copy.

    Claude Code, in a terminal:

    claude mcp add digup -- node "C:/Users/you/Downloads/digup-mcp.mjs" --code ABCD-EFGH-JKLM

    Claude Desktop, Cursor and others, in the app's MCP servers settings (Claude Desktop: Settings, Developer, Edit Config; Cursor: Settings, MCP):

    {
  "mcpServers": {
    "digup": {
      "command": "node",
      "args": ["C:/Users/you/Downloads/digup-mcp.mjs", "--code", "ABCD-EFGH-JKLM"]
    }
  }
}

    On a Mac or Linux the path looks like /Users/you/Downloads/digup-mcp.mjs. Restart the app after you change its settings.

  5. Ask your app

    DigUp's status changes to Connected within about 30 seconds. Then ask, for example:

    Use DigUp to find the lists on https://books.toscrape.com and scrape the book list, 3 pages.

    DigUp opens the page in a background tab, collects the rows and closes the tab again.

What your app can ask DigUp

ToolWhat it does
digup_tabsLists the web pages open in your Chrome (tab id, title, address), so the agent can work on a page you already have open and signed in to.
digup_find_listsFinds the tables and repeating lists on a page, best match first, with a sample of each. Give a url or a tabId.
digup_scrapeReturns the rows of one list as objects with clean column names (Title, Price, Email…). Options: list (which list, default the best), pages (1–50), mode (auto, next, scroll or none), delaySeconds (at least 1) and maxRows (up to 5,000).

More things to ask

  • Scrape the job list in my open tab, all pages up to 10, and save it as a CSV.
  • Find the lists on this page and tell me which one has the prices.
  • Scrape the first 200 products here, then compare the prices with last week's file.

Let browser agents use DigUp

  1. Turn on "Let AI agents use DigUp on pages"

    On DigUp's AI tools page. It works on pages you open or reload from then on.

  2. Tell your agent how to ask

    The AI tools page has this text ready to copy. The agent runs it in the page:

    window.addEventListener('message', (e) => {
  if (e.data && e.data.digup === 'response') console.log(JSON.stringify(e.data));
});
window.postMessage({ digup: 'request', id: 1, action: 'find_lists' }, '*');
window.postMessage({ digup: 'request', id: 2, action: 'scrape', options: { list: 0, maxRows: 500 } }, '*');

    Each response has the same id and either result or error. scrape takes list, maxRows (up to 5,000), and pages with mode: 'scroll' for infinite scroll. Action help lists every option.

While this is on, websites can see that DigUp is installed. A page can only get data from itself, which it can already read, never from another site. For pages with a Next button, use the side panel or the MCP link.

Rules and limits

  • Off until you turn them on. Both options live on DigUp's AI tools page and can be turned off there at any time.
  • Polite by design. At least 1 second between pages, at most 50 pages and 5,000 rows per request.
  • No getting past checks. Bot checks, CAPTCHAs and sign-in pages are reported to the agent, never bypassed. The agent asks you to handle them in Chrome.
  • Paired and local. DigUp answers the MCP server only after it sends your pairing code, and only on 127.0.0.1.
  • Nothing sent to us. Pages are read in your own Chrome. What your AI app does with the rows is up to that app. See the privacy policy.
  • Respect each site. Only collect data you are allowed to use, and follow each website's terms.

Troubleshooting

The status says "Not connected"
Your app starts the MCP server when it starts, so restart the app. Check that node --version shows 18 or later and that the path to digup-mcp.mjs is right.
"The wrong pairing code"
After you press New code, copy the command or settings again from the AI tools page and restart your app.
The port is in use
Pick another port on the AI tools page; the copied command then includes --port.
The first request waits a while
DigUp looks for the server every 30 seconds, and at once when you switch to Chrome. Click into Chrome to connect sooner.
The agent says a page needs a check or a sign-in
Open that page in Chrome, sign in or finish the check yourself, then ask again with that tab.
Browser agent gets no answer
Reload the page after turning the option on, and check that "Allow DigUp on all sites" is on.

Still stuck? Use Report a problem in DigUp's menu.

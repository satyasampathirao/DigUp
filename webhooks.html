What you can do with DigUp's webhook

A webhook is an address from an automation tool. DigUp sends your rows there, and the tool passes them on to almost any app. It works with Zapier, Make, n8n and most other automation tools, and nothing is sent anywhere until you press Send or turn on a page check.

Get started in three steps

  1. Make a webhook in your automation tool

    Zapier: create a Zap with the trigger Webhooks by Zapier, Catch Hook. Make: start a scenario with Webhooks, Custom webhook. n8n: add a Webhook node set to POST. Copy the address it gives you.

  2. Send from DigUp

    In DigUp's panel press the send button (the paper plane next to JSON), paste the address under Webhook address and press Send. Chrome asks you once to allow DigUp to contact that site. Your tool now has a sample to build on.

  3. Add what should happen next

    In your tool, add an action after the webhook, such as one of the examples below. To repeat it automatically, turn on Check this page for changes in the same window and choose The webhook above.

Addresses must start with https://. A tool running on your own computer, such as n8n at http://localhost, works too.

Add the rows to a Google Sheet you already use

DigUp's New Google Sheet makes a new sheet each time. To keep adding to one sheet (a price log, a lead list), use the webhook:

  • Zapier: after Catch Hook, add Google Sheets, Create Multiple Spreadsheet Rows and map each column to the matching field of rows.
  • Make: after the webhook, add an Iterator on rows, then Google Sheets, Add a Row.
  • n8n: after the Webhook node, use Split Out on rows, then Google Sheets, Append Row.

For a page check, map changes.added instead of rows to log only what is new.

Get an alert when a page changes

Turn on Check this page for changes with The webhook above. DigUp calls the webhook only when something changed (and once for the first check), with a short summary in changes.counts.

  • Price drops: check a shop's list every day; in your tool, keep only changes.changed rows whose price went down, then send yourself an email.
  • New jobs or listings: check a search results page every 12 hours and post each item in changes.added to Slack, Teams or email.
  • Something disappeared: changes.removed lists rows that are gone, such as a product out of stock.

Straight to Slack or Discord, no automation tool needed: paste a Slack Incoming Webhook address (it starts with https://hooks.slack.com/) or a Discord channel webhook (Channel settings, Integrations, Webhooks). DigUp then sends a short message instead of JSON, for example:

DigUp: 1 new, 1 changed on shop.example.com
https://shop.example.com/boots
New:
• Snow Boot · $99.00
Changed:
• Trail Boot: Price: $89.00 → $79.00 (−11%)

Price drops are listed first. Discord messages never mention or ping anyone.

Checks run while Chrome is open. A check that meets a bot check or sign-in page stops and tells you on DigUp's Saved setups page; it never gets past it.

Send leads to your CRM

Scrape a directory or member list (with an Email or Phone column), then in your tool add an action such as HubSpot, Create Contact, Pipedrive, Create Person or Salesforce, Create Record for each item in rows. Use a filter to skip rows without an email.

Only collect contact details you are allowed to use, and follow each website's terms and your local privacy laws.

More apps

The same pattern works for Notion and Airtable databases (one record per row), Microsoft Excel online, Trello or Asana tasks, Discord messages, and thousands of other apps your automation tool connects to.

What DigUp sends

One POST with a JSON body. Rows are objects keyed by your column names, just like DigUp's JSON export:

{
  "source": "DigUp",
  "site": "shop.example.com",
  "url": "https://shop.example.com/boots",
  "sentAt": "2026-11-08T09:30:00.000Z",
  "columns": ["Title", "Price", "Link"],
  "rowCount": 2,
  "rows": [
    { "Title": "Trail Boot", "Price": "$89.00", "Link": "https://shop.example.com/p/1" },
    { "Title": "Rain Boot", "Price": "$45.00", "Link": "https://shop.example.com/p/2" }
  ]
}

A page check adds what changed since the last check (up to 500 of each kind):

"changes": {
  "counts": { "added": 1, "changed": 1, "removed": 0 },
  "added": [ { "Title": "Snow Boot", "Price": "$99.00", "Link": "..." } ],
  "changed": [ { "before": { "Price": "$89.00", ... }, "after": { "Price": "$79.00", ... } } ],
  "removed": [],
  "key": "Link"
}
firstCheck
true on a check's first run, which sends every row and no changes.
truncated
Present when there were more than 5,000 rows; only the first 5,000 are sent.
changes.key
The column DigUp used to match rows between checks (usually a link), or null when whole rows were compared.

Privacy

DigUp sends rows only to the address you paste, only when you press Send or a check you turned on finds changes. Nothing passes through DigUp's developer. What happens to the rows next is up to your automation tool and the apps you connect. See the privacy policy.
